Developer Implementation Review · Area 08

Simulation Webhooks

Voice AI Platform

The question

How do simulation webhooks affect what happens after a simulation run, and what can a developer reasonably conclude from the webhook data about the simulation's outcome?

What we investigated

We examined the simulation lifecycle events sent to a configured webhook, including what information is provided when a simulation starts and ends, and how that information relates to the simulation's evaluation.

What we found

Simulation webhooks provide lifecycle and run information.

A simulation.run.ended event establishes that the simulation run ended and provides information about that run. It does not, by itself, establish that the simulation passed its success criteria or that the intended external outcome occurred.

Why it matters

A developer could receive a successful webhook delivery and treat it as evidence that the simulation succeeded.

The webhook and the simulation evaluation answer different questions: the webhook reports what happened to the run, while the evaluation determines whether the configured success conditions were satisfied.

Evidence

A controlled review of the simulation lifecycle and evaluation path showed that the ended event can be received separately from inspecting the criteria used to determine whether the simulation passed.

Result

The webhook provides lifecycle/run evidence, not an independent pass/fail or business-outcome guarantee.

Implementation implication

Developers need to distinguish between receiving confirmation that a simulation run ended and verifying what the simulation actually established. Evaluation results, transcript or message data, tool execution, and external system state may require separate inspection.

What this demonstrates

DaxMac investigates what product events actually establish and whether developers can safely use those events as evidence of the outcome they intend to validate.
